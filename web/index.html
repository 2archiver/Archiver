✓ Browser generation is enabledIt will activate only for requests that need writing or explanations.

Browser generation is always enabled for writing, explanations, coding and plans. Its status is shown here and beside the chat box; it activates on demand. There is nothing to install and no download button: the first generative request fetches model assets into this browser’s cache and reuses them afterwards. Archiver picks the runtime automatically — WebGPU where the browser has it, and a WebAssembly (CPU) runtime where it does not, which is what most Safari installs get. Keep this page open while it prepares. Offline mode, Data Saver, or a browser with neither runtime will leave the instant tools running instead.

3.3Latest2026-09-26
A read of the sources, not a stock paragraph — and a plan on every prompt

3.2 ended every web answer with “Additional Thoughts & Lateral Angles”: a paragraph picked by keyword bucket, identical across every topic in the bucket, and a fallback (“ask who pays, what must stay on, and what the default is”) that made no sense for Benito Mussolini. That is gone.

  • The read is built from the retrieved text. What kind of thing the subject is comes from the lead sentence (“an Italian politician, journalist, and dictator”), the span of years and the turning-point sentence come from the extracts, agreement and disagreement come from comparing the sources, and a “why” asked of sources that only narrate is called out as unanswered rather than filled with a generic angle. Two subjects cannot produce the same paragraph.
  • No heading, no emoji, no hedging. The read is the closing paragraph of the answer, the way any mainline assistant ends a grounded answer. It commits: contested claims a source states as fact are repeated as fact, claims it frames as allegations are repeated as allegations, and a yes-or-no whose key word never appears in the sources is answered with that absence.
  • Thinking on literally every prompt. Every route now states a one-line plan — arithmetic, commands, pasted text, conversation, a matched card and its strength, a web read (“3 sources describe Mussolini as a person… lead with the strongest line, then what they agree on, then my own read”) — and the panel opens on every answer. A generated answer whose model skipped its planning line shows the pipeline’s plan instead of nothing.
  • With the on-device model, a web-grounded answer receives the facts and the draft read separately and is asked to finish with its own specific, committed assessment — sharpening or contradicting the draft, never pasting it.
  • “What do you think?” after a search answers with the read built for that subject, not a rotating stock line.
  • Yes-or-no questions (“was mussolini a socialist”) are recognised as such and restated honestly.

3.22026-09-26
Safari gets a real runtime, and every answer shows its thinking

Two fixes people actually hit: the iPhone keyboard, and Safari having no way to generate at all.

  • Generation on Safari without WebGPU. A second vendored runtime — llama.cpp compiled to WebAssembly — is chosen automatically when the browser has no usable GPU. No flag to enable, nothing to install, no download button. Same model family, CPU instead of GPU, slower and labelled as such.
  • iOS keyboard rewritten. The shell is now sized from the layout viewport, not the visual one. The thread no longer collapses while typing and the blank gutter under the composer after the keyboard closes is gone. Pinch-zoom and toolbar collapse are no longer mistaken for a keyboard.
  • Thinking on every prompt. Generated answers start with one planning line; it is lifted out of the reply and shown in the Thought process panel. Instant answers get a panel too, built from what actually ran — matched card and its score, the arithmetic, the query searched, the backend chosen and why, tokens and seconds.
  • Better small-model output. Task-specific approaches for eight request types, a presence penalty against repetition, and streaming cleanup of filler openers, blank-line padding, sign-offs and unclosed code fences.
  • Data Saver is now actually honored, as 3.1 claimed. Offline, Data Saver, or a browser with neither runtime leaves instant tools working and says why.
  • Fields are 16px on touch devices, so iOS stops zooming the page on focus and leaving it zoomed.

3.12026-09-26
Built-in AI, designed for Render Free
  • Pinned WebLLM 0.2.80 runtime and license shipped with the website; no inference-library CDN call and no deployment-time npm step.
  • Qwen2.5 0.5B initializes automatically for requests that need generation — no Settings detour, no manual install.
  • f16/f32 variant chosen from GPU capabilities; weights, tokenizer and GPU library fetched straight into the browser cache.
  • Server preparation moved off the response path; deterministic comparisons, formatting, extractive summaries, action items and a corrected calculator.
  • Render Blueprint pinned to plan: free, with SQLite’s ephemerality documented rather than papered over.
